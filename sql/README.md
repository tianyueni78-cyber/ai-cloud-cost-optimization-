# SQL实用导航

先根据业务问题选择文件，再运行。完整思路和填空卡见[九阶段模板](../learning/数据分析九阶段填空模板.md)；公式、时间、粒度和关联逻辑见[指标与数据映射](../learning/指标与数据映射.md)。

## 运行方式

在仓库根目录执行：

```powershell
python run_sql.py sql/【文件名.sql】
```

例如：

```powershell
python run_sql.py sql/02_data_audit.sql
```

## 选择哪份SQL

| 文件 | 什么时候用 | 回答什么 | 输入 |
|---|---|---|---|
| `00_data_orientation.sql` | 第一次打开一张表 | 字段、类型、样例和行数是什么 | 原始CSV |
| `01_source_inventory.sql` | 收到多张表 | 每张表的规模、时间和粒度是什么 | 原始CSV |
| `02_data_audit.sql` | 认识数据后 | 是否存在重复、空值、范围、格式和关联问题 | 原始CSV |
| `03_data_audit_detail.sql` | 第一轮发现问题后 | 每类异常的具体数量、类型和关联改善空间 | 原始CSV |
| `04_data_audit_context.sql` | 异常数量已知 | 空值是否适用、字段组合是否违反业务规则 | 原始CSV＋数据字典 |
| `05_data_audit_resolution.sql` | 准备清洗 | 哪些保留、回填、去重，冲突时保留哪条 | 原始CSV＋审计结论 |
| `06_business_overview.sql` | 清洗完成后 | 成本、采购结构、利用率、负载和月度趋势 | `outputs/cleaned/` |

推荐顺序：

```text
00—01 认识数据
→ 02—03 量化质量问题
→ 04 判断业务含义
→ 05确定处理规则
→ 运行Pandas清洗与测试
→ 06正式分析
```

## 换项目时哪些不变

通常保留：

- `DESCRIBE`、`LIMIT`、`COUNT` 的认识结构；
- 空值、重复、范围、枚举和关联率的审计顺序；
- `GROUP BY`、占比、环比和窗口函数；
- 先审计、再清洗、再正式分析；
- 清洗前后与总账对账。

必须替换：

- CSV路径、表名和字段名；
- 主键、业务重复键和关联键；
- 时间字段、分析粒度和时区；
- 合法枚举、合理范围和允许为空条件；
- 总账费用口径、业务量单位和SLA规则。

## 每次修改前的检查

```text
这份SQL要回答什么业务问题？
结果一行代表什么？
使用哪个时间口径？
哪些单位不能混合？
JOIN是一对一、多对一还是可能放大行数？
结果怎样与来源总量核对？
```

## 常见错误

- 在PowerShell命令中给SQL的 `*` 加反斜杠；
- 直接把月度账单与小时使用明细连接；
- 使用内连接丢掉无资源池的共享费用；
- 对百分比简单平均；
- 把 `requests`、`jobs` 和 `k_pages` 相加；
- 把 `invoice_month` 当成资源实际使用时间；
- 只看查询成功，不检查分项是否回到总计。

# 数据质量检查清单

对每张新数据表按顺序执行，不要跳过前面的基础检查。

## 1. 文件层

- [ ] 文件存在且可以读取。
- [ ] 编码和分隔符正确。
- [ ] 文件名和版本明确。
- [ ] 文件大小合理。
- [ ] 文件校验值或来源已记录。

## 2. 结构层

- [ ] 列名符合数据字典。
- [ ] 没有意外新增或缺失列。
- [ ] 数据类型可以转换。
- [ ] 日期、金额和百分比单位明确。
- [ ] 行粒度已写清。

## 3. 完整性

- [ ] 总行数已记录。
- [ ] 每列空值数量和比例已统计。
- [ ] 必填字段没有无法解释的空值。
- [ ] 时间范围完整。
- [ ] 应出现的团队、产品、区域和月份存在。

## 4. 唯一性

- [ ] 候选主键已定义。
- [ ] 完全重复已统计。
- [ ] 主键重复已统计。
- [ ] 业务键重复已统计。
- [ ] 已定义保留记录的优先顺序。

## 5. 有效性

- [ ] 枚举字段只包含允许值。
- [ ] 数值范围符合物理和业务含义。
- [ ] 日期开始不晚于结束。
- [ ] 金额计算关系正确。
- [ ] 类型转换失败已统计。

## 6. 一致性

- [ ] ID 大小写和分隔符差异已检查。
- [ ] 相同概念在不同表中的单位一致。
- [ ] 产品、团队和资源归属没有无法解释的冲突。
- [ ] 使用月份、发票月份和记录时间已区分。
- [ ] SLA 使用了正确生效期间。

## 7. 可关联性

- [ ] JOIN 前检查右表键唯一性。
- [ ] 标准化前关联率已计算。
- [ ] 标准化后关联率已计算。
- [ ] 未匹配记录已单独保存。
- [ ] JOIN 后行数和金额没有意外放大。

## 8. 及时性

- [ ] 数据最新日期符合预期。
- [ ] 延迟记录数量已统计。
- [ ] 跨月账单已识别。
- [ ] 业务事件时间与分析窗口一致。

## 9. 业务合理性

- [ ] 利用率与分配容量关系合理。
- [ ] 推理、训练和批处理使用正确指标。
- [ ] 不同 `volume_unit` 没有直接相加。
- [ ] 低利用率结合 SLA 和容灾解释。
- [ ] 高利用率同时检查容量风险。

## 10. 报告要求

每项问题记录：

- 检查方法；
- 证据和数量；
- 影响范围；
- 对分析的影响；
- 建议处理；
- 严重等级；
- 是否阻断后续工作。

## 完成定义

只有检查过、量化过、记录过并确定处理方式的问题，才算完成审计。发现问题但没有说明影响和处理规则，不算完成。

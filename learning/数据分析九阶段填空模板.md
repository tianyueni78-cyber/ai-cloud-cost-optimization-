# 数据分析九阶段填空模板

这份手册用于解决一个实际问题：**知道分析目标，但不知道怎样把业务问题翻译成 SQL、Pandas 和交付物。**

不要从空白页开始写代码。按下面的固定接口逐层翻译：

```text
业务语言
→ 填写工作卡
→ 判断问题类型
→ 选择模板
→ 替换【占位符】
→ 运行
→ 验证
→ 解释
→ 形成交付物
```

> `【占位符】` 不是可以直接运行的 SQL。必须替换成当前项目真实的表名、字段名、条件或数值。

## 使用规则

1. 先通过根目录的 [数据分析导航](../数据分析导航.md) 判断当前阶段。
2. 只填写当前阶段，不要一次填完九个阶段。
3. 不确定的答案写“待验证”，不要凭感觉写成事实。
4. SQL 模板只替换变量，不重新发明查询结构。
5. 运行后必须填写“结果说明”和“完成检查”。
6. 业务规则不能从 SQL 语法中推导，必须来自业务背景、数据字典或负责人确认。

# 第一阶段｜业务理解 Business Understanding

## 什么时候使用

- 收到一句模糊需求，例如“成本太高”“客户在流失”“配送太慢”；
- 不知道应该分析哪个指标；
- 不知道分析结果要支持什么行动。

这一阶段通常不写 SQL。先把业务需求变成可分析问题。

## 1.1 项目目标填空

```text
帮助【一个决策者】
在【至少两个业务约束】下，
决定【至少三个可执行行动】，
从而改善【一个核心指标】，
同时保护【一至两个保护指标】。
分析范围为【明确时间 + 数据实际覆盖的业务范围】。
```

常见候选值：

| 占位符 | 可以填什么 |
|---|---|
| `【决策者】` | 运营负责人、财务负责人、产品负责人、销售主管、供应链经理 |
| `【业务约束】` | 预算、SLA、法规、合同、产能、人员、服务范围 |
| `【可执行行动】` | 调整容量、修改价格、增加人员、改变采购、优化流程 |
| `【核心指标】` | 成本、收入、准时率、转化率、留存率、利用率、单位成本 |
| `【保护指标】` | SLA达标率、服务可用性、业务容量、收入、客户体验 |
| `【分析范围】` | 最近12个月、某区域、某产品、付费客户、生产环境 |

不要混淆四类内容：

- **业务约束**：行动不能违反的边界，例如合同不能提前取消、不能破坏 SLA；
- **可执行行动**：决策者看完分析后确实有权实施的事情，例如改变采购组合；
- **核心指标**：这个项目主要希望改善的一个结果；
- **保护指标**：改善核心指标时不能明显恶化的一至两个结果。

目标不是把所有“好指标”都写进去。核心指标过多，后续分析就无法围绕一个明确决定展开。

## 1.2 数据支持检查

```text
当前数据能否计算核心指标：【是 / 否 / 待验证】
当前数据能否计算保护指标：【是 / 否 / 待验证】
分析时间是否落在数据覆盖范围内：【是 / 否 / 待验证】
分析地区、产品或客户范围是否存在于数据中：【是 / 否 / 待验证】
决策者是否有权实施所列行动：【是 / 否 / 待确认】
```

如果选择“否”，应删去该指标或范围，或者明确记录“需要补充什么数据”，不能假装现有数据能够回答。

## 1.3 指标口径填空

```text
指标名称：【名称】
业务含义：【它衡量什么】
计算公式：【分子 / 分母】
单位：【USD / 元 / 个 / 次 / % / 秒 / 天】
时间粒度：【小时 / 日 / 周 / 月】
分析维度：【团队 / 产品 / 区域 / 渠道 / 客户类型】
目标或基准：【目标值 / 去年同期 / 上月 / 预算】
```

## 1.4 进入下一阶段前回答

```text
我们要支持的决定是：【填写】
至少需要的数据对象是：【填写】
不能仅靠数据决定的业务规则是：【填写】
事实、假设和建议是否已经分开：【是 / 否】
```

## 常见错误

- 把成本、收入、留存率、转化率等所有重要指标同时列为核心指标；
- 写入数据中不存在的地区、客户或时间范围；
- 列出当前决策者无权实施的行动；
- 使用“SLA 运算”“优化一下”等含义不明确、无法验证的表达；
- 把数据不支持的指标直接写入目标，而没有标记“待补充数据”；
- 行动只写“降低成本”“提高效率”等结果，没有写怎样改变业务。

## 固定与变化

- 固定：决策者、行动、核心指标、保护指标、约束、范围六项必须明确，并通过数据支持检查。
- 变化：具体 KPI、目标值、业务限制和利益相关者。

## 完成条件与交付物

- 能用一句话说明项目目标；
- 每个分析问题都能对应一个潜在行动；
- 输出：问题定义、指标口径、约束清单。

深入教程：[理解业务问题](02_business_understanding.md)

# 第二阶段｜数据认识 Data Orientation

## 什么时候使用

- 第一次拿到 CSV、Excel、数据库表；
- 不知道一行代表什么；
- 不知道主键、单位、时间字段和表关系。

## 2.1 每张表先填数据卡

```text
表名：【表名】
业务对象：【订单 / 客户 / 事件 / 账单 / 库存 / 资源 / 其他】
我猜一行代表：【填写；不确定可写待验证】
候选主键：【字段名 / 复合字段】
主要时间字段：【字段名】
金额或数量单位：【填写】
可能的外键：【字段名】
需要关联的表：【表名】
仍不理解的字段：【字段名】
```

常见行粒度：

- 一笔订单；
- 一个客户；
- 一次事件；
- 一条账单行；
- 一个资源池；
- 一个对象在一个小时/一天/月的汇总。

## 2.2 查看结构

业务问题：字段有哪些，工具推断成什么类型？

```sql
DESCRIBE
SELECT *
FROM read_csv_auto('【数据文件路径】');
```

候选替换：

```text
【数据文件路径】
data/orders.csv
data/customers.csv
data/events.csv
```

## 2.3 查看实际样例

```sql
SELECT *
FROM read_csv_auto('【数据文件路径】')
LIMIT 【样例行数】;
```

`【样例行数】` 常用 5、10 或 20。样例用于理解格式，不用于证明数据质量。

## 2.4 查看规模和时间范围

```sql
SELECT
    COUNT(*) AS row_count,
    COUNT(DISTINCT 【候选主键】) AS distinct_key_count,
    MIN(TRY_CAST(【时间字段】 AS TIMESTAMP)) AS first_time,
    MAX(TRY_CAST(【时间字段】 AS TIMESTAMP)) AS last_time
FROM read_csv_auto('【数据文件路径】', all_varchar = true);
```

如果主键由多个字段组成：

```sql
COUNT(DISTINCT (【字段1】, 【字段2】))
```

## 2.5 查看分类取值

```sql
SELECT
    【分类字段】,
    COUNT(*) AS row_count
FROM read_csv_auto('【数据文件路径】')
GROUP BY 【分类字段】
ORDER BY row_count DESC;
```

分类字段候选：状态、类型、地区、产品、渠道、服务等级。

## 2.6 看完后重新填写

```text
实际一行代表：【填写】
候选主键：【填写】
主键是否已经验证唯一：【是 / 否，数据审计再验证】
主要时间字段和时区：【填写】
表间关系：【一对一 / 一对多 / 多对一 / 带生效期】
不可直接相加的单位：【填写】
```

## 固定与变化

- 固定：结构、样例、行数、粒度、主键、关系、时间、单位八项。
- 变化：表名、字段名、复合主键、时区和业务粒度。

## 完成条件与交付物

- 能用一句话说明每张表一行代表什么；
- 能画出表关系；
- 输出：数据清单和关系图。

深入教程：[认识数据](03_data_orientation.md)；SQL实现参考：[00](../sql/00_data_orientation.sql)、[01](../sql/01_source_inventory.sql)。

# 第三阶段｜数据审计 Data Audit

## 什么时候使用

- 已经认识数据，但不知道是否可靠；
- 准备清洗或正式分析之前；
- 表连接结果异常、数字明显不合理。

## 3.1 审计参数卡

```text
表名：【表名】
候选主键：【字段】
业务重复键：【字段组合】
必填字段：【字段列表】
允许为空字段及适用条件：【字段 + 条件】
枚举字段及合法值：【字段 + 值列表】
数值字段及合理范围：【字段 + 最小/最大】
外键及权威表：【外键 → 维表主键】
时间字段及业务时区：【填写】
跨字段业务规则：【公式或逻辑】
```

## 3.2 主键重复模板

```sql
SELECT
    【候选主键】,
    COUNT(*) AS row_count
FROM 【表或CSV读取表达式】
GROUP BY 【候选主键】
HAVING COUNT(*) > 1
ORDER BY row_count DESC;
```

`【表或CSV读取表达式】` 可以是：

```sql
read_csv_auto('data/orders.csv')
```

也可以是：

```sql
raw_orders
```

## 3.3 业务重复模板

```sql
SELECT
    【业务键1】,
    【业务键2】,
    COUNT(*) AS row_count,
    COUNT(DISTINCT 【记录ID】) AS distinct_record_ids
FROM 【表】
GROUP BY 【业务键1】, 【业务键2】
HAVING COUNT(*) > 1;
```

业务键候选：对象ID + 时间、订单ID + 商品ID、资源池 + 小时、客户 + 产品 + 生效日期。

## 3.4 空值模板

```sql
SELECT
    COUNT(*) AS total_rows,
    COUNT(*) FILTER (
        WHERE 【字段】 IS NULL OR TRIM(CAST(【字段】 AS VARCHAR)) = ''
    ) AS missing_rows,
    ROUND(
        100.0 * COUNT(*) FILTER (
            WHERE 【字段】 IS NULL OR TRIM(CAST(【字段】 AS VARCHAR)) = ''
        ) / NULLIF(COUNT(*), 0),
        2
    ) AS missing_pct
FROM 【表】;
```

空值很多时继续按业务类型拆分：

```sql
SELECT
    【业务类型字段】,
    COUNT(*) AS total_rows,
    COUNT(*) FILTER (WHERE 【字段】 IS NULL) AS missing_rows
FROM 【表】
GROUP BY 【业务类型字段】;
```

## 3.5 类型、范围和枚举模板

```sql
SELECT
    COUNT(*) FILTER (
        WHERE NULLIF(TRIM(【字段】), '') IS NOT NULL
          AND TRY_CAST(【字段】 AS 【目标类型】) IS NULL
    ) AS conversion_failures,
    MIN(TRY_CAST(【字段】 AS 【目标类型】)) AS minimum,
    MAX(TRY_CAST(【字段】 AS 【目标类型】)) AS maximum
FROM 【原始文本表】;
```

`【目标类型】` 候选：`DOUBLE`、`BIGINT`、`DATE`、`TIMESTAMP`、`BOOLEAN`。

枚举检查：

```sql
SELECT 【枚举字段】, COUNT(*) AS row_count
FROM 【表】
GROUP BY 【枚举字段】
ORDER BY 【枚举字段】;
```

## 3.6 表间关联率模板

```sql
SELECT
    COUNT(*) AS source_rows,
    COUNT(*) FILTER (WHERE target.【目标主键】 IS NOT NULL) AS matched_rows,
    ROUND(
        100.0 * COUNT(*) FILTER (WHERE target.【目标主键】 IS NOT NULL)
        / COUNT(*),
        2
    ) AS match_rate_pct
FROM 【来源表】 source
LEFT JOIN 【目标表】 target
  ON source.【外键】 = target.【目标主键】;
```

## 3.7 跨字段规则模板

```sql
SELECT COUNT(*) AS violation_rows
FROM 【表】
WHERE 【字段A】 【比较符】 【字段B】;
```

候选规则：结束时间早于开始时间、活跃量超过分配量、净额不等于总额减折扣、百分比超出0—100。

## 3.8 审计发现记录卡

```text
问题：【名称】
异常数量和比例：【填写】
证据样例：【填写】
属于错误 / 结构性空值 / 可接受噪声 / 待确认：【选择】
影响哪些指标或连接：【填写】
建议处理：【保留 / 标准化 / 回填 / 去重 / 排除 / 待确认】
```

## 固定与变化

- 固定：完整性、唯一性、有效性、一致性、可关联性、及时性、业务规则。
- 变化：主键、允许空值、合法范围、标准格式和业务规则。

## 完成条件与交付物

- 每类异常已量化和分类；
- 已知它会影响什么；
- 输出：审计报告与清洗规则候选。

深入教程：[数据审计](04_data_audit.md)；SQL实现参考：[02—05](../sql/README.md#数据审计知识点对应哪些-sql)。

# 第四阶段｜数据清洗 Data Cleaning

## 什么时候使用

- 审计已经证明问题存在；
- 已经知道处理依据；
- 需要建立可供正式分析使用的干净数据层。

## 4.1 清洗决策卡

```text
审计问题：【填写】
业务证据：【数据字典 / 权威表 / 状态 / 时间 / 负责人确认】
处理动作：【保留 / 标准化 / 去重 / 回填 / 排除】
保留哪条记录以及原因：【填写】
是否保留原始字段：【通常是】
怎样验证处理正确：【填写】
清洗前后允许变化的指标：【填写】
绝对不能变化的指标：【填写】
```

## 4.2 ID标准化模板（Pandas）

```python
df["【标准化字段名】"] = (
    df["【原始ID字段】"]
    .astype("string")
    .str.strip()
    .str.upper()
    .str.replace("_", "-", regex=False)
)
```

常见替换：

```text
【原始ID字段】：customer_id、order_id、resource_pool_id
【标准化字段名】：customer_id_normalized、order_id_normalized
```

## 4.3 类型转换模板

```python
df["【数值字段】"] = pd.to_numeric(
    df["【数值字段】"], errors="coerce"
)

df["【UTC时间字段】"] = pd.to_datetime(
    df["【UTC时间字段】"], errors="coerce", utc=True
)
```

## 4.4 确定性去重模板

完全重复：

```python
rows_before = len(df)
df_clean = df.drop_duplicates()
rows_removed = rows_before - len(df_clean)
```

按业务优先级保留：

```python
df_clean = (
    df.sort_values(
        ["【业务键】", "【优先级字段】"],
        ascending=[True, 【True或False】]
    )
    .drop_duplicates(subset=["【业务键】"], keep="【first或last】")
)
```

优先级候选：更新时间、版本号、数据质量状态、权威来源。没有业务证据时不能随便保留第一行。

## 4.5 权威表回填模板

```python
df = df.merge(
    authority[["【关联键】", "【权威字段】"]],
    on="【关联键】",
    how="left",
    validate="many_to_one",
)

df["【最终字段】"] = df["【原字段】"].combine_first(
    df["【权威字段】"]
)
```

## 4.6 清洗前后验证卡

```text
各表清洗前后行数：【填写】
删除行数能否由规则完全解释：【是 / 否】
主键或业务键是否唯一：【是 / 否】
关联率是否达到预期：【填写】
空值是否被错误填成0：【是 / 否】
金额、业务量、时间范围是否异常变化：【填写】
原始数据是否保持不变：【是 / 否】
```

## 固定与变化

- 固定：原始层只读、规则有依据、处理可重复、前后可对账。
- 变化：标准化、去重、回填和排除的具体规则。

## 完成条件与交付物

- 清洗代码可从原始数据重新生成结果；
- 关键不变量验证通过；
- 输出：清洗数据、代码、测试、质量汇总。

深入教程：[数据清洗](05_data_cleaning.md)；项目实现：[clean_data.py](../src/clean_data.py)。

# 第五阶段｜探索分析 Business Overview / EDA

## 什么时候使用

- 清洗层已经验证；
- 想回答发生了什么、发生在哪里、何时发生；
- 尚未进入原因和行动结论。

## 5.1 指标—维度—时间工作卡

```text
核心指标：【成本 / 收入 / 订单数 / 客户数 / 准时率 / 利用率】
计算公式：【填写】
单位：【填写】
时间字段：【使用时间 / 订单时间 / 发票时间 / 其他】
时间粒度：【日 / 周 / 月】
分析维度：【团队 / 产品 / 区域 / 渠道 / 类型】
比较基准：【上期 / 同比 / 目标 / 预算】
不可混合的单位或粒度：【填写】
```

## 5.2 总量模板

```sql
SELECT
    COUNT(*) AS row_count,
    COUNT(DISTINCT 【业务对象ID】) AS object_count,
    SUM(【核心数值字段】) AS total_value
FROM 【清洗表】
WHERE 【分析范围条件】;
```

如果没有范围条件，可以删除 `WHERE`。

## 5.3 分类结构和占比模板

```sql
WITH grouped AS (
    SELECT
        【分类维度】,
        SUM(【指标字段】) AS metric_value
    FROM 【清洗表】
    GROUP BY 【分类维度】
)
SELECT
    【分类维度】,
    metric_value,
    ROUND(
        100.0 * metric_value / SUM(metric_value) OVER (),
        2
    ) AS share_pct
FROM grouped
ORDER BY metric_value DESC;
```

## 5.4 时间趋势和环比模板

```sql
WITH monthly AS (
    SELECT
        DATE_TRUNC('month', 【时间字段】) AS metric_month,
        SUM(【指标字段】) AS metric_value
    FROM 【清洗表】
    GROUP BY metric_month
)
SELECT
    metric_month,
    metric_value,
    ROUND(
        100.0 * (
            metric_value / LAG(metric_value) OVER (ORDER BY metric_month) - 1
        ),
        2
    ) AS month_over_month_pct
FROM monthly
ORDER BY metric_month;
```

## 5.5 效率模板

```sql
SELECT
    【分析维度】,
    SUM(【投入指标】) AS total_input,
    SUM(【产出指标】) AS total_output,
    SUM(【投入指标】) / NULLIF(SUM(【产出指标】), 0) AS cost_per_output
FROM 【清洗表】
GROUP BY 【分析维度】;
```

投入候选：成本、工时、资源小时。产出候选：订单、请求、收入、处理量。单位不同的产出不能混加。

## 5.6 观察结果模板

```text
我观察到：【事实和数字】
变化集中在：【时间 / 地区 / 产品 / 团队】
目前只能说明：【描述性事实】
还不能判断：【原因或行动】
下一步需要结合：【业务量 / 价格 / 效率 / 结构 / 事件】验证。
```

## 固定与变化

- 固定：总量、趋势、结构、效率、业务切片。
- 变化：KPI、维度、单位、时间字段和比较基准。

## 完成条件与交付物

- 能回答发生了什么、何时开始、集中在哪里；
- 没有把描述性关系写成原因；
- 输出：分析 SQL 与基础事实表。

深入教程：[SQL探索](06_sql_exploration.md)；项目实现：[06](../sql/06_business_overview.sql)。

# 第六阶段｜成本归因 Cost Attribution

## 什么时候使用

- 费用需要分到团队、产品、客户或渠道；
- 有共享费用、抵扣、调整或承诺费用；
- 分组汇总不能直接代表责任归属。

## 6.1 归因设计卡

```text
总账来源表：【表名】
进入总账的费用类型：【列表】
不进入或只展示的费用类型：【列表】
直接归属键：【资源ID / 订单ID / 账户 / 成本中心】
共享费用类型：【列表】
共享费用驱动因素：【用量 / 收入 / 用户数 / 资源量 / 固定比例】
抵扣和调整归属规则：【填写】
使用月份与发票月份口径：【填写】
允许的对账误差：【0 / 舍入容差】
```

## 6.2 定义总账范围

```sql
SELECT
    SUM(【金额字段】) AS ledger_total
FROM 【账单表】
WHERE 【费用类型字段】 IN (【纳入费用类型列表】);
```

费用列表写法示例：

```sql
('Usage', 'Credit', 'Adjustment', 'Support')
```

示例不能直接照搬，必须根据当前账单规则重新定义。

## 6.3 直接归属模板

```sql
SELECT
    COALESCE(billing.【直接归属字段】, dimension.【后备归属字段】)
        AS attributed_owner,
    SUM(billing.【金额字段】) AS direct_cost
FROM 【账单表】 billing
LEFT JOIN 【权威维表】 dimension
  ON billing.【关联键】 = dimension.【关联键】
WHERE 【直接归属条件】
GROUP BY attributed_owner;
```

## 6.4 共享费用分摊模板

```sql
WITH driver AS (
    SELECT
        【归属对象】,
        SUM(【分摊驱动字段】) AS driver_value
    FROM 【驱动数据表】
    GROUP BY 【归属对象】
), shared AS (
    SELECT SUM(【金额字段】) AS shared_cost
    FROM 【账单表】
    WHERE 【共享费用条件】
)
SELECT
    driver.【归属对象】,
    shared.shared_cost
      * driver.driver_value
      / NULLIF(SUM(driver.driver_value) OVER (), 0) AS allocated_shared_cost
FROM driver
CROSS JOIN shared;
```

## 6.5 对账模板

```sql
SELECT
    【总账金额】 AS ledger_total,
    SUM(【归因后金额】) AS attributed_total,
    【总账金额】 - SUM(【归因后金额】) AS reconciliation_difference
FROM 【归因结果】;
```

## 6.6 敏感性分析卡

```text
当前分摊驱动：【填写】
备选驱动：【填写】
更换驱动后最大归属变化：【填写】
结论是否依赖主观假设：【是 / 否】
```

## 固定与变化

- 固定：定义总账、直接优先、共享分摊、只计一次、最终对账。
- 变化：费用范围、归属键、驱动因素、时间口径和容差。

## 完成条件与交付物

- 全部归因金额能回到总账；
- 分摊方法可解释并能测试备选方案；
- 输出：归因明细、口径说明、对账控制表。

深入教程：[成本归因](07_cost_attribution.md)。

# 第七阶段｜原因分析 Root-cause Analysis

## 什么时候使用

- 已经发现成本、收入、效率或服务指标发生变化；
- 需要回答为什么，而不只是发生了什么；
- 有多个可能驱动因素。

## 7.1 原因假设卡

```text
变化指标：【填写】
变化开始时间：【填写】
集中维度：【团队 / 产品 / 地区 / 渠道】
假设1——业务量变化：【填写】
假设2——价格或费率变化：【填写】
假设3——效率变化：【填写】
假设4——结构占比变化：【填写】
假设5——业务事件或外部因素：【填写】
每个假设需要的证据：【填写】
```

## 7.2 通用拆解公式

```text
总成本 = 业务量 × 单位成本

单位成本又可能受到：
价格 × 资源效率 × 采购结构 × 产品/客户结构
```

其他领域可以替换为：

```text
收入 = 客户数 × 客单价
订单量 = 流量 × 转化率
延迟 = 处理时间 + 排队时间 + 运输时间
```

## 7.3 量价效率对比模板

```sql
SELECT
    DATE_TRUNC('month', 【时间字段】) AS metric_month,
    SUM(【总金额】) AS total_value,
    SUM(【业务量】) AS total_volume,
    SUM(【总金额】) / NULLIF(SUM(【业务量】), 0) AS value_per_unit,
    AVG(【效率指标】) AS avg_efficiency
FROM 【分析表】
GROUP BY metric_month
ORDER BY metric_month;
```

## 7.4 事件前后模板

```sql
SELECT
    CASE
        WHEN 【时间字段】 < 【事件时间】 THEN 'before'
        ELSE 'after'
    END AS event_period,
    AVG(【目标指标】) AS avg_metric,
    COUNT(*) AS sample_rows
FROM 【分析表】
WHERE 【时间字段】 BETWEEN 【事件前起点】 AND 【事件后终点】
GROUP BY event_period;
```

前后变化只能提供证据，不能自动证明因果。还要检查同期其他变化和对照组。

## 7.5 结论证据卡

```text
事实：【指标何时、在哪里变化】
支持的原因：【证据】
排除或削弱的原因：【证据】
仍存在的替代解释：【填写】
结论置信度：【高 / 中 / 低】
还需要什么数据：【填写】
```

## 固定与变化

- 固定：先定位变化，再提出竞争假设，再逐个找证据。
- 变化：指标分解公式、事件、对照组和业务机制。

## 完成条件与交付物

- 结论具有证据链，而不是“两个指标一起变化”；
- 主原因和替代解释分开；
- 输出：驱动因素分析与证据表。

# 第八阶段｜预测 Forecasting

## 什么时候使用

- 需要预算、容量或目标规划；
- 需要比较未来不同业务情景；
- 历史数据和口径已经稳定。

## 8.1 预测设计卡

```text
预测目标：【成本 / 收入 / 订单 / 容量 / 客户数】
预测粒度：【日 / 周 / 月】
预测期限：【未来几期】
历史训练范围：【填写】
验证范围：【保留最近几期】
已知驱动因素：【业务量 / 价格 / 季节性 / 活动 / 合同】
基线方法：【上期值 / 移动平均 / 同比 / 趋势】
情景参数：【保守 / 基准 / 激进】
评价指标：【MAE / MAPE / 业务容差】
```

## 8.2 先建立月度序列

```sql
SELECT
    DATE_TRUNC('month', 【时间字段】) AS metric_month,
    SUM(【预测目标字段】) AS target_value
FROM 【清洗或归因表】
GROUP BY metric_month
ORDER BY metric_month;
```

## 8.3 简单基线模板（Pandas）

```python
series = monthly.sort_values("【时间字段】").copy()

series["baseline_previous_period"] = series["【目标字段】"].shift(1)
series["baseline_moving_average"] = (
    series["【目标字段】"]
    .rolling(window=【窗口期数】)
    .mean()
    .shift(1)
)
```

`【窗口期数】` 候选：3个月、4周、7天，必须与业务周期匹配。

## 8.4 情景模板

```python
last_value = series["【目标字段】"].iloc[-1]

scenarios = {
    "conservative": last_value * (1 + 【保守增长率】),
    "base": last_value * (1 + 【基准增长率】),
    "aggressive": last_value * (1 + 【激进增长率】),
}
```

增长率必须来自历史、业务计划或管理假设，并明确来源。

## 8.5 误差模板

```python
valid = series.dropna(subset=["【实际值】", "【预测值】"])
mae = (valid["【实际值】"] - valid["【预测值】"]).abs().mean()
mape = (
    (valid["【实际值】"] - valid["【预测值】"]).abs()
    / valid["【实际值】"].replace(0, pd.NA)
).mean()
```

## 8.6 预测结果卡

```text
基线预测：【填写】
保守 / 基准 / 激进情景：【填写】
历史回测误差：【填写】
影响最大的假设：【填写】
预测不能覆盖的事件：【填写】
何时需要重新预测：【填写】
```

## 固定与变化

- 固定：先做简单基线、保留验证集、报告误差和假设。
- 变化：目标、周期、驱动因素、模型和情景参数。

## 完成条件与交付物

- 复杂模型至少优于简单基线；
- 预测值带情景、误差和假设；
- 输出：预测表、回测结果和情景说明。

深入教程：[预测](08_forecasting.md)。

# 第九阶段｜优化 Optimization

## 什么时候使用

- 已经知道问题、原因和未来需求；
- 需要比较多个行动；
- 成本节省不能脱离业务约束。

## 9.1 优化机会卡

```text
问题对象：【团队 / 产品 / 资源 / 流程 / 客户群】
当前基线成本或损失：【填写】
建议行动：【填写】
预计节省或收益公式：【填写】
一次性实施成本：【填写】
实施时间：【填写】
业务约束：【SLA / 合同 / 容量 / 法规 / 兼容性】
最坏风险：【填写】
缓解措施：【填写】
负责人：【填写】
成功指标：【填写】
```

## 9.2 节省计算模板

```sql
SELECT
    【优化对象】,
    SUM(【当前成本】) AS baseline_cost,
    SUM(【优化后估计成本】) AS optimized_cost,
    SUM(【当前成本】) - SUM(【优化后估计成本】) AS gross_savings,
    (
        SUM(【当前成本】) - SUM(【优化后估计成本】)
    ) - 【实施成本】 AS net_savings
FROM 【机会明细表】
GROUP BY 【优化对象】;
```

## 9.3 优先级评分模板

```text
净收益评分：【1—5】
实施难度评分：【1—5，越高越难】
业务风险评分：【1—5，越高越危险】
实施速度评分：【1—5】

优先级 = 收益 + 速度 - 难度 - 风险
```

权重和公式必须由组织偏好决定，不能假装是客观真理。

## 9.4 建议表达模板

```text
建议：【采取什么行动】
对象和范围：【填写】
预计净收益：【金额 / 比例】
实施时间：【填写】
不会触碰的约束：【填写】
主要风险：【填写】
缓解措施：【填写】
先试点还是全面实施：【填写】
需要谁批准：【填写】
```

## 9.5 不能直接优化的常见情况

- 利用率低但承担容灾或备用角色；
- 合同到期前无法无成本取消；
- 高优先级客户要求专用容量；
- 不同硬件或资源不能等价替换；
- 短期节省会造成长期迁移成本；
- 数据证据不足，只能先试点。

## 固定与变化

- 固定：基线、收益、实施成本、约束、风险、时间和负责人。
- 变化：行动方案、节省公式、风险偏好和优先级权重。

## 完成条件与交付物

- 每个建议都能追溯到分析证据；
- 同时说明收益、风险、时间和业务影响；
- 输出：优化机会清单、优先级和实施路线图。

深入教程：[优化](09_optimization.md)。

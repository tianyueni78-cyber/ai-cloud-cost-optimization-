# 成果交付指南

完成九阶段分析后再打开本页。顺序是：

```text
验证后的分析表 → Power BI → 管理层摘要 → GitHub作品集
```

## 一、Power BI仪表盘

### 开始条件

- 数据审计和清洗完成；
- 成本口径已对账；
- 主要指标已有稳定分析表；
- 时间、团队、产品和资源维度明确。

不要直接把全部原始小时数据塞进第一版Power BI，也不要在Power Query中另写一套无法追溯的清洗逻辑。

### 数据模型

```text
事实表：月度成本、月度使用、SLA表现、优化行动
维度表：日期、团队、产品、资源、区域、采购方式
```

检查：维度主键唯一；维度到事实为一对多；筛选通常单向；事实表之间不直接多对多连接。

### 四个页面

| 页面 | 回答的问题 | 主要内容 |
|---|---|---|
| Executive Overview | 总体发生了什么 | 总成本、趋势、可实现节省、关键风险 |
| Cost Drivers | 成本由什么构成 | 团队、产品、GPU、区域、采购方式、单位成本 |
| Capacity & SLA | 优化是否安全 | 利用率、峰值容量、备用容量、延迟、可用性 |
| Optimization Actions | 应该采取什么行动 | 收益、风险、负责人、30/60/90天计划 |

### 最小DAX

```DAX
Total Net Cost =
SUM(fact_billing[net_cost_usd])
```

```DAX
Weighted GPU Utilization =
DIVIDE(
    SUM(fact_usage_monthly[utilization_weighted_sum]),
    SUM(fact_usage_monthly[allocated_gpu_hours])
)
```

```DAX
MoM Cost Growth =
VAR PreviousMonthCost =
    CALCULATE([Total Net Cost], DATEADD(dim_date[date], -1, MONTH))
RETURN
    DIVIDE([Total Net Cost] - PreviousMonthCost, PreviousMonthCost)
```

### 验证

- KPI卡片与SQL控制表一致；
- 筛选后数字仍能对账；
- 日期连接使用正确时间口径；
- 百分比使用分子分母重算，不平均已聚合百分比；
- 每个图表回答一个业务问题；
- GitHub同时保存 `.pbix`、页面截图和 `dashboard/README.md`。

## 二、管理层摘要

管理层顺序不是“我先清洗再写SQL”，而是：

```text
结论 → 影响 → 原因 → 行动 → 风险 → 需要批准什么
```

### 模板

```markdown
# Executive Summary

## 核心结论

## 关键发现

## 建议行动

## 30/60/90天计划

## 需要管理层决策

## 风险与限制

## 证据索引
```

每项发现包含：

```text
事实数字 + 比较基准 + 业务解释 + 为什么重要
```

每项行动包含：

```text
行动 + 可实现净收益 + 时间 + 负责人 + SLA/容量/合同条件
```

数字必须注明时间、单位、分母、预测情景以及节省是理论值还是净收益。事实、推断和假设分开。

## 三、GitHub作品集

### README故事线

1. 一句话项目价值；
2. 业务背景和决策问题；
3. 数据规模与关系；
4. 方法和工具；
5. 关键发现；
6. 优化行动及预计影响；
7. 仪表盘截图；
8. 复现步骤；
9. 限制和后续工作。

### 应提交

- 核心SQL和Python；
- 数据字典和可复现说明；
- 正式报告；
- Power BI文件和截图；
- 能追溯关键数字的小规模结果表。

### 不应提交

- `.venv/`、缓存、密钥和个人绝对路径；
- 无法解释的临时文件；
- 空报告；
- 可以重新生成的大型中间文件；
- 没有核对过的结论和夸大的节省数字。

### 一分钟验收

新访客只看README，应能回答：

```text
公司遇到了什么问题？
分析了什么数据？
采用了什么方法？
发现了什么？
建议做什么？
这体现了什么岗位能力？
```

如果必须打开多个Notebook才能回答，README还没有完成。

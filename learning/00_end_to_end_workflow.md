# 00｜端到端数据分析工作流

## 一张图看完整项目

```text
收到业务问题
  ↓
理解公司、产品、团队和决策目标
  ↓
盘点文件、字段、粒度、主键和表关系
  ↓
审计完整性、唯一性、有效性、一致性和及时性
  ↓
用可复现规则建立干净数据层
  ↓
用 SQL 计算趋势、结构、效率和异常现象
  ↓
联合 SLA、库存、账单和事件解释原因
  ↓
建立成本归因、预测和优化方案
  ↓
用 Power BI 展示关键指标
  ↓
用管理层摘要提出行动与决策请求
  ↓
整理 GitHub 作品集
```

## 工作目录与数据流

| 数据层 | 放在哪里 | 可以修改吗 | 用途 |
|---|---|---|---|
| 原始层 | `data/*.csv` | 不可以 | 保存收到的原始事实 |
| 样本层 | `data/sample/*.csv` | 不用于正式分析 | 快速认识字段和测试代码 |
| 清洗层 | 本地 `outputs/clean/` | 由代码重新生成 | 统一类型、ID 和重复处理规则 |
| 分析层 | 本地 `outputs/analysis/` | 由 SQL/Notebook生成 | 指标、汇总和模型输入 |
| 展示层 | `dashboard/`、`reports/` | 可以 | 面向招聘方和管理层的结果 |

`outputs/` 建议加入 `.gitignore`，避免把大量可重复生成的中间数据提交到 GitHub。

## 每个阶段的固定动作

### 1. 明确问题

- 谁提出问题？
- 他要做什么决策？
- 需要什么指标支持？
- 哪些限制不能违反？

### 2. 确认输入

- 使用哪些文件？
- 每行代表什么？
- 时间和金额口径是什么？
- 关联键是否可靠？

### 3. 编写可重复步骤

- SQL 放在 `sql/`。
- Python 或 Notebook 放在 `notebooks/`。
- 不在 Excel 中进行无法复现的大量手工修改。
- 原始数据不覆盖。

### 4. 验证输出

- 总量是否与输入核对？
- JOIN 是否放大行数？
- 单位是否一致？
- 时间范围是否正确？
- 空值、重复和异常值如何处理？

### 5. 解释业务意义

分析结果至少回答：

```text
发生了什么？
为什么发生？
影响有多大？
是否需要行动？
行动有什么条件和风险？
```

### 6. 保存证据并提交

- 保存代码，而不是只保存截图。
- 报告引用查询和数据口径。
- 提交信息说明完成了什么业务成果。

## 软件在流程中的位置

| 软件 | 什么时候打开 | 主要作用 |
|---|---|---|
| GitHub 浏览器 | 阅读资料、查看提交和展示成果 | 项目门户 |
| VS Code | 几乎整个项目 | 编辑 SQL、Python、Markdown 和 Git 操作 |
| DuckDB | 数据审计、清洗、SQL 探索和归因 | 直接查询大型 CSV |
| Python/Pandas | 清洗补充、预测、统计和绘图 | 程序化数据处理 |
| Jupyter | 需要边运行边解释的分析 | 组合文字、代码和输出 |
| Power BI Desktop | 数据稳定后 | 数据模型、DAX、图表和交互仪表盘 |

## 阶段退出规则

不要因为“代码运行了”就进入下一阶段。只有同时满足以下条件才算完成：

- 输出可以重新生成；
- 关键数字已核对；
- 业务口径写清楚；
- 已记录限制和风险；
- 对应文件已提交到 Git。

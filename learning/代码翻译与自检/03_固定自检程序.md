# 固定自检程序

代码能运行，只能说明语法基本通过；不能证明业务口径和结果正确。每个正式指标都按下面顺序过关，AI 写的代码也不例外。

## 总流程

```text
定义关 → 输入关 → 语法关 → 主键关 → 公式关
→ 空值范围关 → 关联关 → 对账关 → 时间关 → 合理性关 → 可复现关
```

## 1. 定义关：先写六句话

在代码前写清：

1. 主表是哪张；
2. 来源粒度是什么；
3. 输出粒度是什么；
4. 数值字段和完整公式是什么；
5. 筛选、费用和时间口径是什么；
6. 是否需要关联，关联后想补充什么。

任一句说不清，先回到[指标与数据映射](../指标与数据映射.md)，不要靠试代码猜答案。

## 2. 输入关：确认代码读到的是预期数据

### SQL

```sql
DESCRIBE SELECT * FROM 【输入表】; -- 例：read_csv_auto('outputs/cleaned/cloud_billing.csv')
SELECT COUNT(*) AS row_count FROM 【输入表】;
SELECT * FROM 【输入表】 LIMIT 10;
```

### Pandas

```python
print(df.shape)
print(df.columns.tolist())
print(df.dtypes)
print(df.head(10))
```

判断：路径、表版本、字段、行数、类型和样例是否符合预期。

## 3. 语法关：从最小查询逐层增加

不要一次运行整段复杂代码。顺序是：

```text
先读取10行 → 加一个筛选 → 加一个聚合 → 加一个分组 → 最后才加JOIN和窗口函数
```

每加一层都观察行数、列数和一两个样例值。报错时使用各翻译模板末尾的语法清单。

## 4. 主键关：证明没有重复计数

### SQL

```sql
SELECT
    COUNT(*) AS total_rows,
    COUNT(DISTINCT 【候选主键】) AS distinct_keys, -- 例：billing_line_id
    COUNT(*) - COUNT(DISTINCT 【候选主键】) AS extra_rows
FROM 【主表】;
```

### Pandas

```python
total_rows = len(df)
distinct_keys = df["【候选主键】"].nunique(dropna=False)
extra_rows = total_rows - distinct_keys
```

若是组合主键，Pandas 使用 `df.duplicated(subset=[【字段列表】])`；SQL 使用 `GROUP BY 【完整字段组合】 HAVING COUNT(*) > 1`。

## 5. 公式关：逐行验证金额或业务恒等式

### SQL

```sql
SELECT COUNT(*) AS violation_rows
FROM 【主表】
WHERE ABS(
    【结果字段】 - (【组成字段1】 - 【组成字段2】) -- 例：net_cost_usd - (gross_cost_usd - discount_usd)
) > 【允许误差】;                              -- 金额例：0.01
```

### Pandas

```python
difference = (
    df["【结果字段】"]
    - (df["【组成字段1】"] - df["【组成字段2】"])
).abs()
violations = df.loc[difference > 【允许误差】]
```

异常不一定是算错，也可能是税费、舍入或字段定义不同；先查数据字典和费用类型。

## 6. 空值、范围和单位关

至少检查：

- 主键、数值、分组和关联字段是否为空；
- 百分比是否在合理范围；
- 金额、GPU 数量、延迟等是否出现不合理负数；
- 相加或相除的字段单位是否一致；
- 空值是否被代码默认跳过或错误填成 0。

### SQL 范围模板

```sql
SELECT COUNT(*) AS violation_rows
FROM 【主表】
WHERE 【数值字段】 < 【合理下界】
   OR 【数值字段】 > 【合理上界】
   OR 【数值字段】 IS NULL;
```

## 7. 关联关：先验证关系，再关联

固定检查四件事：右表键是否唯一、未匹配多少、行数是否异常增长、核心总额是否变化。

### SQL

```sql
-- A. 右表关联键必须符合预期唯一性
SELECT 【右关联键】, COUNT(*) AS rows_per_key
FROM 【右表】
GROUP BY 【右关联键】
HAVING COUNT(*) > 1;

-- B. 关联前后对账
WITH joined AS (
    SELECT l.*, r.【右关联键】 AS matched_key
    FROM 【左表】 l
    LEFT JOIN 【右表】 r
      ON l.【左关联键】 = r.【右关联键】
)
SELECT
    (SELECT COUNT(*) FROM 【左表】) AS rows_before,
    COUNT(*) AS rows_after,
    COUNT(*) FILTER (WHERE matched_key IS NULL) AS unmatched_rows,
    (SELECT SUM(【金额字段】) FROM 【左表】) AS amount_before,
    SUM(【金额字段】) AS amount_after
FROM joined;
```

### Pandas

```python
amount_before = left["【金额字段】"].sum()
rows_before = len(left)

joined = left.merge(
    right,
    how="left",
    left_on="【左关联键】",
    right_on="【右关联键】",
    validate="many_to_one", # 根据真实关系替换
    indicator=True,
)

checks = {
    "rows_before": rows_before,
    "rows_after": len(joined),
    "unmatched_rows": int(joined["_merge"].eq("left_only").sum()),
    "amount_before": amount_before,
    "amount_after": joined["【金额字段】"].sum(),
}
```

通常成本归因要求 `amount_before == amount_after`；否则必须解释差异，不能继续出报告。

## 8. 对账关：小计必须回到总计

```sql
WITH detail AS (
    SELECT
        【分类字段】,                      -- 例：charge_type
        SUM(【金额字段】) AS subtotal
    FROM 【主表】
    WHERE 【总账筛选条件】
    GROUP BY 【分类字段】
)
SELECT
    SUM(subtotal) AS sum_of_subtotals,
    (SELECT SUM(【金额字段】) FROM 【主表】 WHERE 【总账筛选条件】) AS grand_total,
    SUM(subtotal) - (SELECT SUM(【金额字段】) FROM 【主表】 WHERE 【总账筛选条件】) AS difference
FROM detail;
```

团队、采购方式、GPU 型号或地区的小计，都应与同口径总计相等；共享和未归属费用要单独显示，不能静默丢弃。

## 9. 时间关：同一指标不能偷换时间

检查：

1. 主时间字段是否来自指标主表；
2. 起止边界是否覆盖完整周期；
3. 使用期间与发票月是否被混为一谈；
4. 不完整月份是否被当作完整月份做环比；
5. 跨月或延迟入账差异能否解释。

主视图与辅助视图可以不同，但标题必须写明口径。

## 10. 合理性关：结果是否可能是真的

不靠感觉猜具体数值，而是检查：

- 数量级是否与账单规模和资源规模相符；
- 各部分占比之和是否约等于 100%；
- 成本大涨时业务量、单价、采购结构或事件是否有相应变化；
- 低利用率是否可能来自高优先级、容灾或最低备用容量；
- 建议是否违反 SLA、未来增长或合同约束。

异常结果先当作“待解释”，不要立刻当作业务结论。

## 11. 可复现关：别人能否重新得到结果

确认：

- 原始数据未被覆盖；
- 输入路径和输出路径明确；
- 清洗规则有记录；
- 查询不依赖手工改过但未保存的数据；
- 从干净环境按说明运行可以得到同一结果；
- 结果文件标注生成口径和时间。

## AI 代码审查十问

1. 主表选对了吗？
2. 来源粒度和输出粒度是什么？
3. 数值字段和公式符合指标定义吗？
4. 筛选条件是否漏项、重项或写反？
5. 时间字段和边界正确吗？
6. 主键或业务键会导致重复计算吗？
7. JOIN 的关系、方向和键正确吗？
8. JOIN 前后行数、金额和未匹配数怎样变化？
9. 分类小计能回到同口径总计吗？
10. 结果支持什么行动，又不能支持什么结论？

只要有一问答不出来，就不能因为代码“运行成功”而采信结果。

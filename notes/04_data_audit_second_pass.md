# 04｜数据审计第二轮

## 目的

补全第一轮被终端省略的空值和范围结果，分类业务重复，比较 ID 标准化前后的行级关联率，并用 UTC 复核时间范围。

## 输入

```powershell
python run_sql.py sql/03_data_audit_detail.sql
```

## 结果说明

- 业务重复不仅是相同记录 ID 的重复，还包括不同 ID 描述同一资源池同一小时的记录。
- 利用率和可用性空值需要在计算指标时明确排除或保留，不能填成 0。
- 延迟只适用于在线推理，排队时间主要适用于训练或批处理；大量空值可能是结构性空值，必须按负载验证。
- 合同、GPU 小时和费率只适用于部分账单类型；大量空值可能符合计费规则，必须按费用类型验证。
- ID 清洗将两个关键关联提高到 100%，证明标准化规则有实际作用。
- 数值范围未直接违反非负或百分比上限，但是否满足 SLA 需要后续业务比较。
- `EVT-014` 是区域价格事件，不属于单一团队或产品，空值具有合理业务解释。

## 新学到的知识

- 空值是否有问题取决于字段对该类记录是否适用。
- 应比较清洗前后的指标，证明清洗规则带来的价值。
- 时区设置会改变月份边界，月度分析必须固定时区。
- 最小值和最大值只能发现范围问题，不能替代 SLA 或业务合理性判断。
- 审计报告可以标记“待分类”，不应在证据不足时强行给出结论。

## 执行器问题与修复

### 报错

```text
AttributeError: 'NoneType' object has no attribute 'show'
```

### 原因

`CREATE VIEW` 会执行操作，但不返回可显示的结果表。原执行器假设每条 SQL 都有结果，并直接调用 `.show()`。

### 修复

```python
for statement in sql_text.split(";"):
    if statement.strip():
        result = duckdb.sql(statement)

        if result is not None:
            result.show()
```

学到的规则：执行型 SQL 和查询型 SQL 的返回值不同，调用结果方法前应检查是否存在结果对象。

## 第一轮关键输出

- 使用表存在 139 组重复 `usage_record_id`；其余四张表的候选主键未发现重复。
- 业务重复样例既包含相同记录 ID，也包含不同记录 ID。
- GPU 利用率、显存利用率和使用时间戳没有发现非空但无法转换的值。
- 账单净金额等式没有发现不一致。
- 使用表资源池 ID 有 1,307 行非标准格式，团队 ID 有 478 行。
- 账单资源池 ID 有 15 行非标准格式。
- 标准化后，使用和账单中的 58 个不同资源池 ID 均可关联到资源清单。
- 事件表各有 1 行缺少团队和产品；数据字典允许这些字段为空。

## 结果解释

- 主键重复与业务重复是两个不同概念，需要分别处理。
- 格式不统一不等于 ID 无效；标准化后能否匹配才是关键证据。
- 账单算术正确不等于账单口径正确。
- 允许为空不等于自动忽略，仍需判断空值是否符合该类记录的业务含义。
- 终端省略号会隐藏部分结果列，不能对没有看见的数字下结论。

## 时区发现

DuckDB 将 UTC 时间按本机 `+08` 显示，导致完整 UTC 观察期在本地月份中跨越 13 个月。后续查询应先执行：

```sql
SET TimeZone = 'UTC';
```

然后再使用 `DATE_TRUNC('month', timestamp)` 统计月份。

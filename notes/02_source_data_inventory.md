# 02｜五张原始数据表盘点

## 目的

确认五张原始数据表的数据规模、字段数量、DuckDB 推断类型和主要业务用途，为后续数据审计建立地图。

## 使用的软件和文件

- VS Code
- Python 虚拟环境 `.venv`
- DuckDB
- `run_sql.py`
- `sql/01_source_inventory.sql`
- `data/*.csv`

## 输入

运行指定 SQL 文件：

```powershell
python run_sql.py sql/01_source_inventory.sql
```

更新后的 `run_sql.py` 通过 `sys.argv[1]` 接收 SQL 文件路径，因此无需修改执行器即可运行不同 SQL 文件。

## 结果说明

### 数据规模

- `resource_usage` 是最大的事实数据，包含约 50.7 万行小时级记录，后续必须使用 DuckDB 等工具查询，不能依靠人工逐行审阅。
- 资源清单、SLA 和事件属于相对较小的描述或规则数据。
- 账单行数高于资源池数，因为同一资源池可以在不同月份、费用类型和调整记录中多次出现。

### 字段类型

- 使用、账单和事件时间被识别为带时区时间戳。
- GPU 数量、业务量和部分 SLA 目标被识别为整数。
- 利用率、延迟、GPU 小时、费率和金额被识别为小数。
- `end_date` 和 `effective_to` 被识别为文本，需要在正式审计中测试日期转换。

### 五张表的角色

| 表 | 简单理解 | 主要关联字段 |
|---|---|---|
| 资源清单 | 有什么资源 | `resource_pool_id` |
| 使用记录 | 资源每小时怎么用 | `resource_pool_id`、`team_id`、`product_id`、时间 |
| 云账单 | 收了什么费用 | `resource_pool_id`、`team_id`、`contract_id`、月份 |
| SLA | 服务必须达到什么标准 | 团队、产品、负载、区域、生效期间 |
| 业务事件 | 当时发生了什么 | 团队、产品、区域、事件期间 |

## 新学到的知识

- 命令行参数可以指定脚本本次运行的 SQL 文件。
- 一张表必须先确认“行粒度”，才能定义重复和正确汇总方式。
- 主键识别一条记录，外键用于连接其他表。
- 同名字段只是 JOIN 候选，不能替代唯一性和关联率检查。
- CSV 的自动类型推断是初步判断，不是正式的数据质量结论。

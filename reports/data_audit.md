# 数据质量审计报告

## 1. 审计结论

五张原始表已完成唯一性、完整性、有效性、一致性、关联性和时间性检查。审计发现的问题均能通过明确规则处理，不需要修改原始 CSV；数据可以进入清洗阶段，但正式分析必须使用清洗结果。

## 2. 审计范围

| 数据表 | 粒度 | 主要检查 |
|---|---|---|
| `resource_inventory` | 一个GPU资源池 | 主键、必填字段、数量、费率、采购枚举 |
| `resource_usage` | 一个资源池一个UTC小时 | 重复、遥测空值、范围、ID格式、时间 |
| `cloud_billing` | 一条账单费用 | 主键、金额公式、合同、归属、资源池关联 |
| `team_sla` | 一条生效期内的SLA规则 | 主键、目标范围、日期和业务键 |
| `business_events` | 一项业务或技术事件 | 主键、适用范围和时间 |

执行入口：`sql/02_data_audit.sql` 至 `sql/05_data_audit_resolution.sql`。

## 3. 核心发现与处理决定

| 发现 | 证据 | 分类 | 处理决定 |
|---|---|---|---|
| 使用记录完全重复 | 139组相同 `usage_record_id`，非ID内容一致 | 真实重复 | 清洗层每组保留一条 |
| 同一业务小时存在修订 | 120组原始记录与 `-R` 修订记录，仅GPU利用率不同 | 合法修订 | 保留 `-R` 版本 |
| 核心遥测存在空值 | GPU利用率630条、显存利用率398条均为 `partial`；可用性239条均为 `late` | 状态可解释空值 | 保留空值和状态；计算时排除空值并报告覆盖率 |
| 工作负载专属指标为空 | Batch/Training不记录在线延迟；Inference不记录排队时间 | 结构性空值 | 保留为空，不填0 |
| ID格式不统一 | 使用资源池ID 1,307条、使用团队ID 478条、账单资源池ID 15条非标准 | 可修复格式噪声 | 新增标准化ID，保留原始值 |
| 账单团队缺失 | 42条均有资源池，且可从资源清单推导团队 | 可修复归属缺失 | 新增归属团队和来源标记，不覆盖原字段 |
| 合同编号缺失 | 288条OnDemand与132条Owned为空；Reserved和SavingsPlan缺失为0 | 结构性空值 | 保留为空；只对承诺采购要求合同 |
| 账单非用量字段为空 | Support、Credit、Adjustment部分记录无资源池、GPU小时或单价 | 结构性空值 | 按费用类型保留，不当作普通用量行 |
| 事件团队和产品为空 | 1条区域级价格事件不适用单一团队或产品 | 合理业务范围 | 保留为空 |
| 本地月份显示13个月 | UTC数据为2025-08-01至2026-07-31，转为东八区后跨入下一月 | 时间口径风险 | 正式月度分析固定使用UTC |

## 4. 已通过的质量检查

- 资源清单、账单、SLA和事件候选主键无重复；关键标识无缺失。
- GPU数量和有效小时费率均为正；利用率和可用性均在0–100范围内。
- 活跃GPU未超过已分配GPU，业务量无负数。
- `net_cost_usd = gross_cost_usd - discount_usd`，未发现算术不一致账单。
- 采购方式、GPU型号、负载类型、遥测状态和费用类型均符合数据字典枚举。
- ID标准化后，使用表和非空账单资源池与资源清单的匹配率均为100%。
- Reserved和SavingsPlan均有合同；OnDemand和Owned不要求合同编号。

## 5. 清洗规则

1. 原始 CSV 保持不变，清洗结果写入独立目录。
2. ID执行去空格、转大写、下划线转连字符，并保留原始字段。
3. 139条完全重复记录每组保留一条；120条修订组保留 `-R` 行。
4. `partial`、`late` 及业务不适用造成的空值不填0。
5. 账单团队缺失时从资源清单生成归属团队，并记录归属来源。
6. 月度分析统一采用UTC；跨月账单分别保留使用期间和发票月份。
7. 清洗后必须核对行数变化、主键唯一性、关联率和账单总金额。

## 6. 最终判断

原始数据包含有意保留的重复、格式差异、遥测延迟和结构性空值，不能直接用于正式指标计算。上述问题已有可复现且可验证的清洗规则，审计阶段通过，可以进入数据清洗与成本分析。

## 2. 已确认结果

### 2.1 候选主键重复

| 数据表 | 候选主键 | 重复键组数 |
|---|---|---:|
| `resource_inventory` | `resource_pool_id` | 0 |
| `resource_usage` | `usage_record_id` | 139 |
| `cloud_billing` | `billing_line_id` | 0 |
| `team_sla` | `sla_id` | 0 |
| `business_events` | `event_id` | 0 |

使用表存在 139 组重复 `usage_record_id`，属于重要数据质量问题。当前查询尚未确认每组记录是否所有业务字段完全相同，因此不能直接决定删除方式。

### 2.2 使用记录的业务重复

按“标准化资源池 ID + UTC 小时”检查时，样例中同时出现：

- 两行共用同一 `usage_record_id`；
- 两行具有不同 `usage_record_id`。

这说明需要区分主键重复与业务重复。下一轮将统计两类业务重复的完整数量，并比较重复行的指标是否完全一致。

### 2.3 必填标识

- 资源清单的关键字段在当前可见输出中未发现空值。
- 使用表的 `usage_record_id` 未发现空值。
- 账单的 `billing_line_id` 和 `net_cost_usd` 未发现空值。
- SLA 的 `team_id` 和 `product_id` 未发现空值。
- 业务事件中各有 1 行缺少 `team_id` 和 `product_id`。事件字段允许为空，需结合事件类型判断是否属于公司级或区域级事件，不能直接标记为错误。

部分空值统计列被终端省略，下一轮使用“字段名 + 空值数”纵向输出复核。

### 2.4 类型与账单算术

- 非空 GPU 利用率转换失败：0。
- 非空显存利用率转换失败：0。
- 非空使用时间戳转换失败：0。
- `net_cost_usd = gross_cost_usd - discount_usd` 不一致账单行：0。

上述结果只证明格式可转换和基本算术成立，不证明数值范围或账单业务口径一定合理。

### 2.5 ID 格式

| 字段 | 非标准格式行数 |
|---|---:|
| `resource_usage.resource_pool_id` | 1,307 |
| `resource_usage.team_id` | 478 |
| `cloud_billing.resource_pool_id` | 15 |
| `cloud_billing.team_id` | 0 |

标准形式定义为：删除两端空格、转为大写、将下划线改为连字符。当前结果证明存在格式差异，但尚未发现标准化后仍无法识别的资源池 ID。

### 2.6 资源池关联率

| 关联 | 标准化后的不同资源池 ID | 匹配 | 未匹配 | 匹配率 |
|---|---:|---:|---:|---:|
| 使用表 → 资源清单 | 58 | 58 | 0 | 100% |
| 账单 → 资源清单 | 58 | 58 | 0 | 100% |

100% 是标准化后的不同 ID 覆盖率，不代表原始行级精确关联率也是 100%。下一轮需要比较标准化前后的行级匹配率，量化清洗规则的实际影响。

### 2.7 时间口径

终端以 Asia/Shanghai 时区显示：

- 首条：`2025-08-01 08:00:00+08`
- 末条：`2026-08-01 07:00:00+08`
- 本地月份数：13

这并不证明原始 UTC 数据覆盖 13 个月。UTC 区间跨越 12 个完整月份，但转换到 `+08` 后，最后 8 个小时落入本地 8 月。正式月度分析必须显式设置 UTC，避免按本机时区切月。

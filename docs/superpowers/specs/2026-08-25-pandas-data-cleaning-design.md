# Pandas 数据清洗设计

## 目标

用一个可重复执行的 Pandas 脚本清洗五张原始 CSV，为后续 SQL 分析、成本归属和 Power BI 提供统一数据。`data/` 中的原始文件始终保持不变。

## 输入与输出

输入文件：

- `data/resource_usage.csv`
- `data/cloud_billing.csv`
- `data/resource_inventory.csv`
- `data/team_sla.csv`
- `data/business_events.csv`

程序入口为 `src/clean_data.py`。清洗结果写入 `outputs/cleaned/`：

- 五张同名清洗 CSV；
- `quality_summary.csv`，记录各表清洗前后行数和关键处理数量。

`outputs/` 已由 `.gitignore` 排除，因此大体积衍生数据不上传 GitHub；代码、测试、规则和运行说明上传。

## 清洗流程

1. 读取五张原始 CSV。
2. 按数据字典转换日期、UTC 时间、数值和布尔字段。
3. 为 ID 字段新增标准化列：去除两端空格、转为大写、将下划线改为连字符；原字段不覆盖。
4. 清洗使用表：
   - 相同 `usage_record_id` 的完全重复每组保留一行；
   - 同一标准化资源池、同一 UTC 小时存在原始行和 `-R` 修订行时，保留 `-R`；
   - 遥测空值、延迟和排队的结构性空值保持为空。
5. 清洗账单表：
   - 用标准化资源池 ID 关联资源清单；
   - 新增 `attributed_team_id`，优先使用账单团队，缺失时采用资源清单团队；
   - 新增 `team_attribution_source`，取值为 `billing` 或 `inventory`；
   - 合同及非用量费用的结构性空值保持为空。
6. 其余三张表完成类型转换和 ID 标准化，不擅自删除业务记录。
7. 验证关键不变量后才写出结果。

## 关键验证

程序必须在写出前确认：

- 五张输入文件全部存在；
- 使用表标准化业务键唯一；
- `-R` 修订行优先规则生效；
- 账单非空资源池均能关联资源清单；
- 账单归属团队清洗后无空值；
- 清洗没有把结构性空值填成 0；
- 输出目录不等于原始数据目录。

验证失败时程序终止，不写出一套看似正常但不可信的数据。

## 测试策略

使用 Python 标准库 `unittest` 和小型内存 DataFrame，不增加测试依赖。测试覆盖：

- ID 标准化；
- 完全重复去除；
- 原始记录与 `-R` 修订记录的选择；
- 账单团队优先级和资源清单回填；
- 原始空值不被改成 0。

测试先写并确认因功能尚未实现而失败，再编写最小实现使测试通过。最后使用完整数据运行程序，并核对质量汇总。

## 明确不做

- 不修改原始 CSV；
- 不填补没有业务依据的数值；
- 不在本阶段计算成本指标、SLA 达标率或优化建议；
- 不引入配置框架、数据库或额外依赖；
- 不把大体积清洗 CSV 提交到 GitHub。

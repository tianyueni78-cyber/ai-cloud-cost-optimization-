# 公司背景：澄云智能科技

## 1. 公司概况

澄云智能科技（ClearSky AI，以下简称“公司”）是一家虚构的 B2B 人工智能平台企业，总部位于新加坡，在亚太和北美市场提供企业级 AI 服务。公司成立于 2021 年，2025 年进入规模化增长阶段。

本项目中的公司、客户、合同、资源和账单均为合成内容，不对应任何真实企业。

公司的收入主要来自三个产品线：

| 产品线 | 产品 ID | 商业模式 | 主要负载 |
|---|---|---|---|
| 企业知识智能 | `PRD-KNOW` | 按席位和检索量订阅 | 检索、重排、嵌入和摘要推理 |
| 客户交互智能 | `PRD-CONV` | 按调用量和并发等级计费 | 低延迟在线推理、内容安全 |
| 智能文档处理 | `PRD-DOC` | 按页数和处理时限计费 | 批量推理、OCR 后处理、模型微调 |

公司还运营不直接产生收入的研究、模型训练和共享平台能力。这些能力对产品交付十分重要，但费用不能仅凭资源归属直接映射到单一产品。

## 2. 组织与责任

公司设有七个使用 GPU 的业务与技术团队。

| 团队 | 团队 ID | 主要职责 | 典型工作负载 | 业务特征 |
|---|---|---|---|---|
| 基础模型训练 | `TEAM-FMT` | 基础模型继续预训练、蒸馏和大型微调 | Training | 项目制、波峰明显、单次任务成本高 |
| 搜索与检索 | `TEAM-SRCH` | 企业搜索、向量检索和重排服务 | Inference / Batch | 工作日流量明显，企业知识产品增长稳定 |
| 对话式 AI | `TEAM-CONV` | 客服智能体和实时对话模型 | Inference | 延迟要求严格，流量增长快，活动峰值明显 |
| 文档智能 | `TEAM-DOC` | 文档解析、分类、抽取和批处理 | Batch / Training | 月末和季度末存在处理高峰 |
| 托管推理平台 | `TEAM-MIP` | 为各产品提供共享模型端点和容量调度 | Inference | 成本需二次归因，必须保留一定冗余容量 |
| 信任与安全 | `TEAM-TRUST` | 内容审核、提示注入检测和合规模型 | Inference | 利用率可能较低，但关键请求必须同步执行 |
| 应用研究 | `TEAM-RES` | 新模型评估、原型验证和实验 | Training / Batch | 业务量指标不稳定，资源使用不直接对应收入 |

## 3. 云基础设施

公司在两个区域运行 GPU 资源：

- `us-east-1`：主要服务北美客户，容量选择较多，部分 On-demand 单价较低。
- `ap-southeast-1`：主要服务亚太客户，客户数据驻留和低延迟要求更严格，部分 GPU 供应紧张。

资源以 GPU 池为管理单位，而不是以单台机器为单位。一个资源池具有固定的团队归属、产品归属、区域、GPU 型号和采购方式。共享平台资源的 `product_id` 可以为 `PRD-SHARED`。

主要 GPU：A100 40GB、A100 80GB、H100 80GB 和 L40S 48GB。不同型号在性能、显存、价格和软件兼容性方面并不等价。

## 4. 采购方式

| 采购方式 | 数据值 | 业务含义 |
|---|---|---|
| 自有容量 | `Owned` | 长期固定容量，按内部折旧与运维成本形成小时费率 |
| 预留实例 | `Reserved` | 指定 GPU、区域和合同期限的容量承诺 |
| 节省计划 | `SavingsPlan` | 以承诺金额换取折扣，使用范围比 Reserved 灵活 |
| 按需 | `OnDemand` | 无长期承诺，单价高，可应对增长和临时峰值 |

采购决定通常提前数月作出。实际业务增速、产品迁移和 GPU 供应变化可能使原采购假设失效。财务团队关心合同利用率和现金承诺，平台团队则更关心容量安全和故障恢复能力。

## 5. SLA 与容量原则

不同团队和工作负载具有不同 SLA。关键在线服务关注月度可用性、P95 延迟、最大允许排队时间、恢复时间目标和最小备用容量。训练与研究任务通常允许排队或中断，但可能受项目发布日期约束。

- 低利用率不能自动判定为浪费。
- 标记为故障切换或监管隔离用途的容量，必须结合 SLA 和区域限制评估。
- 高平均利用率可能代表效率较高，也可能代表缺少峰值缓冲。
- 共享平台费用需要根据实际业务驱动因素分配，不能全部留在平台团队。
- 采购优化必须考虑合同到期日、容量交付提前期和区域供应限制。

## 6. 业务节奏

在线推理业务具有明显的日内和周内周期。企业客户在工作日产生更多流量，不同区域的峰值时间不同。文档处理在月末和季度末较高；训练任务以多日项目形式运行；大型客户上线、营销活动和版本发布会改变短期或长期需求。

数据覆盖 2025-08-01 至 2026-07-31，期间包含产品发布、大客户上线、区域事故、容量采购、价格调整、模型迁移和季度处理高峰等事件。事件表只记录当时可获得的业务信息，不保证实际影响与预期完全一致。

## 7. 管理层关注的问题

公司管理层希望在不损害客户体验和模型研发计划的前提下控制 GPU 成本。CFO 关注预算偏差、承诺浪费和单位经济性；CTO 关注容量风险、平台效率和技术迁移；各业务负责人关注增长、SLA 和资源获取速度。

分析人员需要将数据质量、技术运行、合同约束和业务价值放在同一框架中判断，而不是仅按照利用率或单价排序后给出回收建议。

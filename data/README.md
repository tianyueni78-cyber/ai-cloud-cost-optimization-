# 数据目录说明

本目录保存澄云智能科技云成本优化练习使用的合成原始数据。所有公司、团队、客户、合同、资源和金额均为虚构内容。

## 文件清单

| 文件 | 粒度 | 主要用途 |
|---|---|---|
| `resource_usage.csv` | 资源池 × UTC 小时 | 利用率、容量、业务量、延迟和可用性分析 |
| `cloud_billing.csv` | 账单费用行 | 成本趋势、采购覆盖和费用归因 |
| `team_sla.csv` | 带生效期的 SLA 规则 | 判断服务要求、备用容量和优化边界 |
| `resource_inventory.csv` | GPU 资源池 | 资源配置、归属、采购方式和生命周期 |
| `business_events.csv` | 业务或技术事件 | 解释发布、客户、事故、迁移和采购背景 |

字段定义、单位、空值规则和业务约束见 [`docs/data_dictionary.md`](../docs/data_dictionary.md)。

完整文件的行数、大小和 SHA-256 校验值见 [`manifest.md`](manifest.md)。

## 完整数据与样本

根数据文件是完整练习数据。`sample/` 中的同名文件仅保留表头和前 200 行，用于在 GitHub 页面快速预览，不适合完成正式分析。

`resource_usage.csv` 约 50 万行。使用 Git 克隆仓库时会同时下载完整数据；不建议直接在电子表格软件中打开整张使用表。

## 使用原则

- 将本目录视为只读原始数据层，不要直接修改原文件。
- 清洗后的数据应写入新的本地目录，并在分析代码中记录生成过程。
- 导入时保留原始文本形式，先完成数据审计，再决定标准化规则。
- 不要在不了解业务含义时把空值替换为 0。
- 不要直接删除所有重复行；先定义完全重复与业务重复的判断规则。
- 成本分析必须明确采用使用月份还是发票月份。
- `UnusedCommitment` 是管理分析口径，不能在不了解计费规则时与总账费用直接相加。

## 推荐读取方式

正式分析阶段可使用 DuckDB、Python、Power Query 或其他能够处理大型 CSV 的工具。数据包本身不要求特定数据库。
